# Data

Three kinds of data appear in this course, and they are kept strictly separate.

```
data/
├── sample/          committed, redistributable, synthetic   -> used by default
├── cache/           downloaded, real, NOT committed         -> opt-in
└── artifacts/       generated by the notebooks (leaderboard, grid datasets)
```

---

## 1. `data/sample/` — committed and synthetic

| file | what it is | generated by |
|---|---|---|
| `energy_synthetic_hourly.csv.gz` | 4 years of hourly load, PV, wind, price, weather | `ai_power_course.synthetic` |
| `power_systems_corpus.txt` | ~270 kB of power-engineering text | `ai_power_course.corpus` |

**These are simulations, not measurements.** Every notebook that loads them
prints a provenance banner saying so, because presenting simulated numbers as
measurements would be a research-integrity failure and is easier to do by
accident than people expect.

The time series is built from physically motivated components — solar geometry
for the clear-sky index, a turbine power curve for wind, a temperature-dependent
load model, a convex merit-order price stack — and its magnitudes are tuned to
resemble Germany:

| quantity | synthetic | Germany, ~2019 |
|---|---|---|
| annual demand | 479 TWh | ~490–500 TWh |
| PV energy | 46 TWh | ~47 TWh |
| wind energy | 98 TWh | ~102 TWh onshore |
| PV capacity factor | 0.117 | ~0.11 |
| wind capacity factor | 0.202 | ~0.20 |
| peak load | ~75 GW | ~80 GW |
| hours with negative price | 4.4% | ~2% |

Close enough that the modelling lessons transfer; not measurements, and never
to be described as such.

The text corpus is in two clearly marked parts: hand-written technical prose
(genuine, written for this course) and synthetic operator logs, disturbance
reports and asset records generated from templates. No real substation, asset or
event is described. Voltage-dependent magnitudes are constrained so that a 20 kV
feeder never carries 400 MW — a corpus that taught wrong orders of magnitude
would be worse than no corpus.

To regenerate either file:

```python
from ai_power_course.data import build_sample_file
from ai_power_course.corpus import write_corpus

build_sample_file()   # energy_synthetic_hourly.csv.gz
write_corpus()        # power_systems_corpus.txt
```

Both are deterministic: the same seed gives byte-identical output.

## 2. `data/cache/` — real data, downloaded, not redistributed

Every experiment in the course runs unchanged on real measurements:

```bash
uv run python scripts/download_data.py
```

That fetches the **Open Power System Data** time-series package (Germany: load,
solar, wind, day-ahead price, 2015 to mid-2020), keeps the four columns the
course uses, and caches ~2 MB locally. `load_energy_data()` then picks it up
automatically; `load_energy_data(source="synthetic")` forces the simulation.

### Why it is not committed

OPSD's time-series package is derived from the ENTSO-E Transparency Platform.
OPSD asks for attribution in a specific form, but its data packages do not carry
a single blanket licence that clearly permits redistribution of the derived
series, and the upstream ENTSO-E terms distinguish between datasets that may be
freely re-used and those that may not.

Rather than guess, this repository does not redistribute it. Students download
it themselves, under the terms the publisher sets, with the attribution string
printed by the loader.

### Required attribution

> Open Power System Data. 2020. Data Package Time series. Version 2020-10-06.
> https://doi.org/10.25832/time_series/2020-10-06.
> (Primary data from various sources, for a complete list see URL.)

Source: <https://data.open-power-system-data.org/time_series/2020-10-06>

### Known limitations of the real data

- It **stops in September 2020**. The 2022 energy crisis, and everything after
  it, is absent.
- Gaps and revisions exist; the loader keeps only the span where all four series
  are populated.
- The German bidding zone changed (DE-AT-LU split in October 2018), so the price
  series is not homogeneous across the whole period.

Running the course on both sources and comparing the conclusions is exercise 3
of tutorial 01, and it is the single most instructive exercise in the notebook.

## 4. Grid data

Tutorial 10 needs no download at all. It uses the IEEE and MATPOWER test cases
that ship with pandapower (`case9`, `case14`, `case24_ieee_rts`, `case30`,
`case39`, `case57`, `case118`, `case33bw`) and generates operating points from
them by perturbing load, generation and topology and solving the AC power flow.

Optionally, realistic German MV/LV benchmark grids are available via SimBench:

```bash
uv sync --extra simbench
```

It is an extra rather than a dependency because the wheel is ~90 MB, and the
tutorial's argument — that one encoder transfers across topologies — is made
just as well with the built-in networks.

## 5. Other open datasets worth knowing

Not used here, but the obvious next steps for a student's own project:

| source | what | note |
|---|---|---|
| [ENTSO-E Transparency](https://transparency.entsoe.eu/) | European load, generation, prices, flows | free account needed for the API |
| [SimBench](https://simbench.de/) | German benchmark grids with time series | |
| [Open Power System Data](https://open-power-system-data.org/) | curated European datasets | the source used here |
| [NREL WIND Toolkit](https://www.nrel.gov/grid/wind-toolkit.html) | US wind resource, ~126k sites | the pretraining corpus behind WindFM |
| [NREL Solar Power Data](https://www.nrel.gov/grid/solar-power-data.html) | US PV plant output | |
| [GridFM DataKit](https://github.com/gridfm/gridfm-datakit) | power-flow / OPF dataset generation | the grown-up version of tutorial 10's sampler |
| [Open Energy Platform](https://openenergyplatform.org/) | European energy system data | |

**Before using any of them:** check the licence, check whether redistribution is
permitted, and record the version and access date. Data provenance is part of
the method, not administrative overhead — which is why it is the first thing
tutorial 01 does.
